# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

BitePlanNow: a Flutter app (portrait-only, Android/iOS). The user picks up to 3 pantry ingredients (or scans them), swipes through AI-generated recipe cards, then cooks step by step. See `README.md` for backend setup and release builds.

## Commands

```bash
flutter pub get
flutter run --dart-define-from-file=env.json     # env.json is gitignored; copy from env.example.json
flutter analyze                                  # lints: flutter_lints
flutter test                                     # all tests (test/cook_test.dart)
flutter test test/cook_test.dart --plain-name "stepSeconds parses durations"   # single test
dart run tool/make_icon.dart                     # regenerates PNGs in assets/icon
flutter build appbundle --release --dart-define-from-file=env.json --obfuscate --split-debug-info=build/symbols
```

Without `SUPABASE_URL`/`SUPABASE_ANON_KEY` the app still launches, but `AiService` throws "Backend not configured" for recipes, scans and dish photos.

## Architecture

Flow: `HomeScreen` (/) → optional `ScanScreen` (/scan) → `DeckScreen` (/deck) → `CookScreen` (/cook). Routes are in `lib/router.dart`; `/cook` takes a `Recipe` via `state.extra` and redirects to `/` if it is missing.

State is Riverpod, all in `lib/providers/providers.dart`: `pantryProvider` (selection capped at `kMaxIngredients`), `deckProvider` (async list of recipes), `pointsProvider` (meal count × `kPointsPerMeal`), `scanQuotaProvider` (3 free scans per session, +1 per rewarded ad, 20 per day persisted via `shared_preferences`; `prefsProvider` is overridden in `main`), `questionQuotaProvider` (recipe requests: 30 free per day, +1 per rewarded ad up to 50, persisted; gated by `ensureQuestionQuota` in `widgets/rewarded_prompt.dart` and counted in `DeckNotifier.generate`), and providers for each service. Tunable constants (caps, ad cadence, confidence threshold) live in `lib/core/config.dart`.

**No vendor API keys in the app.** `lib/services/ai_service.dart` calls Supabase Edge Functions (`supabase/functions/{groq-recipes,gemini-vision,pexels-photo}`), which hold the Groq/Gemini/Pexels keys as Supabase secrets. The app signs in anonymously; `supabase/schema.sql` defines meal history and a per-user daily quota (surfaced as HTTP 429 → `AiException`). All AI failures are normalised to `AiException` with a user-facing message, and the Edge Function responses are the raw vendor payloads (`choices[0].message.content` for Groq, `candidates[0]...text` for Gemini) that the service unwraps and JSON-decodes.

**Scanning is two-tier** (`lib/services/vision_service.dart`): the photo is downscaled to ≤640px in an isolate, ML Kit on-device detection runs first and keeps labels ≥ `kLocalConfidence` that map into the ingredient catalog; if nothing qualifies it falls back to Gemini via the Edge Function. ML Kit's default labels are coarse, so most scans take the cloud path.

Ingredient names are normalised everywhere through `matchCatalog` / `titleCase` in `lib/core/ingredients.dart`; recipes are parsed defensively by `Recipe.tryParse` (invalid ones are dropped, and zero valid recipes is an error).

Ads (`google_mobile_ads`): `lib/services/ads_service.dart` + `lib/widgets/ad_banner.dart`, with an interstitial every `kAdEverySwipes` swipes and a rewarded ad that unlocks one extra scan once the session's free scans are used (`ScanScreen`). Ad unit IDs and the AndroidManifest/Info.plist app IDs are Google test values that must be replaced before release.

## Assets

`assets/icon/` holds the app icon sources (generated by `tool/make_icon.dart`) and `feature_graphic.png` (1024×500 Google Play feature graphic, made by hand from HTML, not by a script). Brand colors are in `lib/core/theme.dart` (`AppColors`: terracotta, sage, cream).
